## 任务：修复"点进标注页图片不显示"问题并加固

你是接手本项目的代码开发工程师。项目是"人机协同图像标注系统"（Flask + Canvas）。上一轮你已完成 P2 画布修复与浅色主题改造，但**用户实测：点进图片预览（标注页）没有图片**。现在由你排查并修复。

### 已排除的事实（接手前你先核对，别再重复排查）

- 后端 `/image/<name>` 路由实测返回 **200 + image/jpeg**（`data/curated/images` 下 328 张图都在）；
- `/api/images`、`/api/annotation/<name>` 返回正常；
- `canvas/app.js` 语法检查通过（node --check），`liveInstances`/`selectedInst`/`setHand`/`setBrushSize` 等函数定义齐全；
- `canvas/style.css` 浅色主题布局正常（`.canvas-area` flex:1、`.canvas-box canvas` inset:0 100%x100%）；
- `templates/annotate.html` 结构正常（含 `#btnHand`、`#cvMain`、`window.APP_CONF`）。

**所以问题大概率是：① 浏览器缓存了旧版 JS/CSS（文件名未变）；② 浏览器端运行时 JS 错误；③ 页面加载时序/画布尺寸异常。按下面的步骤诊断定位，不要盲改代码。**

### 第一步：先排除浏览器缓存（5 分钟）

1. 启动服务（5000 端口如被占用，先让用户关闭旧窗口）：
   `C:\Users\H\miniforge3\envs\imglabel\python.exe app.py`
2. 打开 `http://127.0.0.1:5000`，**按 Ctrl+F5（强制刷新，跳过缓存）**，点进任意一张图。
3. **如果强制刷新后图片出现了** → 问题就是缓存。请直接跳到"第四步：加固"，并在收工时告诉用户"以后修改后要 Ctrl+F5"。
4. 如果强制刷新后**仍然没有图片** → 继续第二步诊断。

### 第二步：浏览器 F12 诊断（定位根因）

打开标注页后按 F12，逐项检查并记录：

1. **Console 面板**：有没有红色报错？把报错信息原文（含文件名和行号）记录下来。重点关注：
   - `ReferenceError` / `TypeError` / `Uncaught ...`
   - 任何关于 `cvMain`、`img`、`draw`、`state` 的报错
2. **Network 面板**：
   - 找 `/image/xxx.jpg` 请求：状态码是 200 还是 404/500？Response 大小是多少？
   - 找 `/canvas/app.js` 和 `/canvas/style.css`：检查 Response Headers 里有没有 `Cache-Control`，确认浏览器拿到的**是不是最新文件**（可在 Network 里点开该请求看"Size"——如果显示 `(from disk cache)` 就是缓存了）
3. **Elements 面板**：
   - 选中 `#cvMain` canvas 元素，看它的 `clientWidth`/`clientHeight` 是否大于 0（若为 0 说明布局塌陷）
   - 在 Console 执行 `document.getElementById("cvMain").width` 和 `.clientWidth` 对比

把以上诊断结果写进汇报，然后按第三步修复。

### 第三步：按诊断结果修复（对应修复）

**若 Console 有 JS 报错：**
- 修复报错本身（变量未定义/空值访问/时序问题），确保 `load()` 正常走完（`fit(); draw();` 都被执行）；
- 特别注意：`load()` 里图片 `onerror` 也会 resolve，导致 `imgW=0` 时画布只画底色不画图——**请在图片加载失败时给出明确反馈**（如 `drawOne` 在 `!state.imgW` 时在画布中央绘制"图片加载失败：<原因>"文字，而不是静默空白），这样以后问题一眼可见。

**若 Network 显示图片 404/500：**
- 检查 `CONF.name` 与 `data/curated/images` 文件名是否完全一致（大小写、扩展名）；
- 检查 `/image/<path:name>` 路由与 `safe_name` 处理。

**若画布 clientWidth/clientHeight 为 0：**
- 修复布局塌陷（`.canvas-box` flex 在 flex-wrap 的工具条挤压下失效等），确保 `boxMain.clientWidth > 0`，`resizeCanvases` 能正确设置 canvas 尺寸。

**若确认是缓存：** 跳到第四步加固。

### 第四步：加固（防止再犯，必须做）

1. 在 `app.py` 中给前端静态资源加缓存禁用（开发阶段合理做法）：
   ```python
   @app.after_request
   def no_cache(resp):
       if resp.path.startswith("/canvas/") or resp.path == "/":
           resp.headers["Cache-Control"] = "no-store, max-age=0"
       return resp
   ```
   （放在 `if __name__ == "__main__":` 之前，注意缩进与现有代码风格一致）
2. 回归：改完后再强制刷新一次，确认图片显示。

### 第五步：回归验收（全部通过才算完成）

1. 列表页 → 点任意一张图 → 标注页**立即显示图片**；
2. 图片显示后：滚轮缩放、H 抓手平移、W 画笔涂抹、三模式切换、保存重开标注仍在——**顺带回归上一轮修复的交互**；
3. 图片加载失败时（可临时改名一张图测试，测完改回）画布显示错误提示文字而非静默空白；
4. 正常刷新页面（不按 Ctrl+F5）也能拿到新代码（第四步加固生效）。
