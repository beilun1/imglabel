# P3 预标注续跑说明（国际版 Qoder 账号切换交接：账号B → 账号A）

> 用途：会员充错账号（充值在账号 A），干活的是账号 B，P3 预标注已由账号 B 跑完约一半。现在切换到有会员的账号 A 续跑。
> 使用方法：退出账号 B → 登录账号 A → 打开项目文件夹 → 先粘贴本说明，再粘贴 P3-提示词.md 全文。

## 第一步：交接动作（先做，别急着跑）
1. `git pull` && `git status` && `git log --oneline -5`
2. 读项目根目录 `CONTEXT.md`（当前状态、坑位、红线、目录约定）
3. 读 `P3指令/P3-提示词.md`（完整任务要求）

## 第二步：确认账号 B 的进度与提交状态
- **确认账号 B 没有任何正在运行的任务**（这是硬前提：账号 B 对话框只保留查看，绝不再发任务；若之前有后台预标注线程在跑，必须等它结束，否则与账号 A 同时写文件会互相覆盖、写坏 JSON）
- 查看 `data/annotations/` 下已有多少个 JSON 文件（账号 B 已跑完约一半，应有约 150-200 个）
- 检查 `prelabel.py`、`app.py`、前端改动**是否已 git 提交**：
  - 已提交 → 直接续跑
  - 未提交（工作区有改动）→ **不要重写这些文件**，基于磁盘上的现有代码继续，这是账号 B 留下的进度
- 检查 `weights/` 下权重是否已存在（`yoloworld.pt` / `yolo26n-seg.pt`）：
  - 已存在 → 跳过下载直接使用
  - 不存在 → 开 Watt Toolkit 加速下载，或提示用户手动放置

## 第三步：续跑（幂等，核心）
- 按 P3-提示词.md 的任务 1 逻辑续跑：**已存在 JSON 的图跳过不覆盖，只处理剩余图**
- 跑完剩余图后，**补做 P3-提示词.md 的完整验收清单（1-9 项）**——账号 B 只跑到中途，画布加载验证、进度条、幂等检查等验收可能还没做，必须逐项实测
- 验收中的任何失败 → 修复后继续，直到 9 项全过

## 第四步：收工（按原协议）
1. `git add -A`（先看 status，不得包含 `data/images/`、`weights/`）→ commit（信息说明 P3 预标注完成，含账号切换续跑）→ push
2. 更新 `CONTEXT.md` 当前状态（P3 完成 + 权重路径 + 输出统计：总数/平均实例数/错误数 + 注明账号切换交接）→ commit → push
3. 汇报：总 JSON 数、剩余处理数、验收 9 项结果、git 提交哈希

## 红线（同原提示词，重申）
- 十类词表顺序/英文名不得改；不修改 app.py 端口（自测用 5001）
- 不动 `data/curated/images/` 原始图；不改 P2 已验收的画布交互逻辑
- 修正计数逻辑不动（P4 的事）；不做三格式导出（P5 的事）
