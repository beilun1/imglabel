# P7 修正指令：切页性能优化（image_items / site_summary 短 TTL 缓存）

> 现象：切换页面（仪表盘 ↔ 图片列表 ↔ 预标注 ↔ 对比 ↔ 导出）时有明显卡顿。
> 根因（已核）：`image_items()` 每次请求都遍历 `data/curated/images/` 下全部 324 张图，并对每张图 `load_ann()` 读 JSON + 算实例数；`site_summary()` 再全量读 `修正记录.json` + 两个统计 JSON。而顶层路由全部 `Cache-Control: no-store`，导致每次切页都从头重算一遍后端 IO。
> 方案：进程内短 TTL 缓存（2 秒），保存标注时显式失效，保证数据实时。

## 改动要求（只动 app.py）

### 1. 给 image_items / site_summary 加 2 秒 TTL 缓存
- 用进程内模块级变量做**弱内存缓存**（不引外部依赖）：
  ```python
  _items_cache = {"t": 0.0, "v": None}
  _summary_cache = {"t": 0.0, "v": None}
  def _cache_get(c):
      return c["v"] if (time.time() - c["t"]) < 2.0 else None
  def _cache_set(c, v):
      c.update(t=time.time(), v=v)
  def _cache_clear():
      _items_cache.update(t=0.0, v=None)
      _summary_cache.update(t=0.0, v=None)
  ```
- `image_items()`：查缓存命中直接返回；未命中则跑原逻辑，填缓存后返回。
- `site_summary(items=None)`：**仅当 `items` 为 None 时**走缓存（此时内部调用 image_items 也会命中缓存）；调用方显式传 items 时不缓存、直接用传入值（保持原有灵活调用不受影响）。
- 顶部确认 `import time` 已存在（缺则补）。

### 2. 保存标注后显式失效缓存
- 在写作文标注 JSON 成功落盘的那条 API 路径（保存 / 保存并下一张 的公共保存函数）里，成功 `json.dump`/写入后调用一次 `_cache_clear()`。
- 保证：用户在画布改完保存的**同一时刻**，切回列表/仪表盘看到的就是最新勾稽，不读 2 秒前的旧数据。

### 3. 明确不动
- `no_cache` after_request 的 `Cache-Control: no-store` **保持原样**（这是让"改代码立即生效"的工程约定，不得改动，防止改 JS/CSS 后不刷新出现假性故障）。
- 不碰 `canvas/app.js` 交互逻辑、标注数据格式、`data/records/`、三模式、导出、对比逻辑。
- 端口、类别词表、round 机制全部不动。
- 不引任何第三方缓存库，不引入全局单例状态跨越请求造成的数据串扰。
