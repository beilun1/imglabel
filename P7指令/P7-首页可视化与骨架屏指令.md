## 任务 1：扩展 /api/dashboard 返回数据（app.py）

在 `site_summary()` 返回的 dict 中**新增两个字段**（其余字段不动）：

### 1.1 `rate_history`：修正率趋势（供 ① 折线/柱状）
- 从 `compare_rows()`（`对比结果.csv`，utf-8-sig）读取每一行的**整体修正率**与**轮次**，组装为数组：
  ```python
  rate_history = [
      {"round": int(r.get("轮次", r.get("round", 0))),
       "rate": float(r["整体修正率"]) if 整体修正率字段存在且可转 float else None}
      for r in compare_rows()
  ]
  ```
- **先读 csv 表头确认列名**（可能为 `轮次`/`整体修正率`，也可能为 `round`/`overall_rate`，以实际为准，不得假设）；列名不一致时按实际列名取值
- 结果应形如 `[{"round": 0, "rate": 0.2375}, {"round": 1, "rate": 0.1522}]`；解析失败返回 `[]`

### 1.2 `class_counts`：十类实例分布（供 ② 条形图）
- 遍历 `data/annotations/*.json`，统计**存活实例**（`mark != "deleted"`）按 `cls` 的计数，返回按类编号 0-9 的有序数组：
  ```python
  class_counts = [0] * len(CLASSES)
  for p in glob.glob(os.path.join(ANN_DIR, "*.json")):
      for inst in read_json(p, {}).get("instances", []):
          if inst.get("mark") != "deleted":
              cls = inst.get("cls")
              if isinstance(cls, int) and 0 <= cls < len(CLASSES):
                  class_counts[cls] += 1
  ```
- **必须加缓存**：复用现有 2 秒 TTL 机制（新增 `_class_cache` 变量，命中逻辑与 `_items_cache` 相同）；**并在 `_cache_clear()` 中一并清空 `_class_cache`**，保证保存标注后首页类别分布实时更新
- 确保 `read_json`、`glob`、`ANN_DIR` 均已导入/定义（缺则补）

## 任务 2：首页三块可视化（templates/index.html）

在现有 `stats-grid` 与 `dashboard-grid` 之间新增一个 `dashboard-viz` 区块（或合理并入布局），**保持 V2 风格、不引第三方库**（全部原生 SVG + 少量 JS）：

### ① 修正率趋势（R0→R1）
- 取 `summary.rate_history`，若含 R0/R1 两行有效值：用原生 SVG 画**两根对比柱**（R0 灰柱、R1 靛蓝柱），柱顶标注 `23.75%` / `15.22%`，R1 柱上方或下方标注 `▼ 8.53pp`（差值）；不足两行则显示"等待 R1 对比数据"
- 无第三方库；SVG 高度约 140px；文案如「人工修正率 · 平台自动统计」

### ② 类别分布条形图
- 取 `summary.class_counts`，横向条形：左侧类名（人/椅子/桌子/沙发/电视/笔记本电脑/杯子/瓶子/盆栽/床——注意与 `CLASSES_ZH` 顺序一致）、右侧数值；条形宽度按最大值归一化，靛蓝色
- 用原生 HTML/CSS（div 宽度百分比）即可，不必 SVG

### ③ 已过审进度环
- SVG 圆环：外圈浅灰轨道、内圈靛蓝进度（`stroke-dasharray` 按 `reviewed/total` 计算），圆心大字 `已过审 233/324` 或 `71.9%`
- 与现有"标注进度"面板信息互补不冲突

### 数据兜底
- `rate_history`/`class_counts` 为空或异常时显示占位文案（如「暂无数据」），**不得白屏、不得 JS 报错**；服务端渲染可用 Jinja 条件，JS 部分加空值保护
