## 提示词（整段复制）

```
你是我的 AI 编程助手。我们正在执行「人机协同图像标注系统」二轮筛选项目的 P0 开工准备阶段。

【第一步：先读上下文】
请先读取项目根目录 C:\Users\H\Desktop\瑞翼二面 下的 CONTEXT.md 和 README.md，
了解项目背景、不可更改项和 Git 交接协议。
注意：这两个文件是任务书的提炼版；凡涉及任务书细节（导出格式规格、训练要求、
提交规则、词表顺序等）以根目录「人机协同图像标注系统·任务书.docx」原文为准，
拿不准时用 pandoc 或 python 提取 docx 文本核实，不要自行脑补任务书要求。

【第二步：检查环境前提】
1. 判断 Miniforge 是否已安装：先查常见安装路径是否存在
   （C:\Users\<用户名>\miniforge3、C:\Miniforge3、C:\ProgramData\miniforge3 等），
   或执行 conda --version。注意：conda 报"不是内部或外部命令"只代表不在 PATH，
   不代表没安装——以安装目录是否存在为准。
2. 检查项目目录 C:\Users\H\Desktop\瑞翼二面 是否已是 git 仓库（git status）；已是则跳过 git init。

【第三步：创建 Python 环境】
先说明：你在 Trae 的终端里找不到 conda 命令是正常的（conda 只初始化在 Miniforge Prompt 里）。
按下面顺序尝试，不要直接报错：
1. 先尝试定位 Miniforge 安装路径（常见：C:\Users\<用户名>\miniforge3 或 C:\Miniforge3），
   找到后使用绝对路径调用，例如：
   & "C:\Users\<用户名>\miniforge3\Scripts\conda.exe" create -n imglabel python=3.10 -y
   & "C:\Users\<用户名>\miniforge3\Scripts\conda.exe" activate imglabel
   （activate 若在脚本中无效，改为直接调用 imglabel 环境内的 python/pip：
    C:\Users\<用户名>\miniforge3\envs\imglabel\python.exe -m pip install ultralytics flask psutil -i https://pypi.tuna.tsinghua.edu.cn/simple）
2. 如果找不到安装路径或上述仍失败，改为「引导模式」：你生成命令，让用户到「开始菜单 →
   Miniforge Prompt」里手动执行，并把输出粘贴回来给你判断，你来排查。
3. 无论哪种方式，最终验证必须看到：python -c "import ultralytics, flask, psutil; print('环境 OK')"
   输出「环境 OK」才算通过；失败则按任务书"常见问题对照"排查（清华源、环境激活等）。

【第四步：完善 .gitignore】
在项目根目录创建/完善 .gitignore，至少排除：模型权重（*.pt）、原始图片压缩包（*.zip）、
__pycache__/、*.pyc、.venv/、.conda/、运行缓存等大文件。注意 dataset/ 和 model/best.pt
是提交必须项，不能忽略。

【第五步：GitHub 私有仓库备份（需要用户配合）】
1. 询问用户是否已有 GitHub 账号；没有则引导注册（github.com）。
2. 引导用户在 GitHub 网页创建一个私有仓库（Private），仓库名建议 imglabel。
3. 用户创建完成后，在本地执行 git remote add origin <仓库地址> 并 git push -u origin master。
4. 如 push 失败提示认证，引导用户用 Personal Access Token（Settings → Developer settings →
   Tokens → Generate new token，勾选 repo 权限）作为密码，或提示开启 Watt Toolkit 加速。
   此步涉及账号，必须停下来让用户操作，不要替用户输入凭据。

【第六步：收尾并留痕（必须）】
1. 更新 CONTEXT.md 第 1 节"当前状态"：标记 P0 完成/进行中，写明本阶段完成内容与下一步。
2. git add -A && git commit -m "P0: 环境搭建与git仓库配置完成" && git push
3. 最后向我汇报：环境 OK 是否通过、.gitignore 内容、GitHub 仓库是否已关联推送。
```

## 你（用户）在这步要配合的 3 件事

| 事项 | 说明 |
|---|---|
| 确认 Miniforge 装在哪 | agent 问你安装路径时如实回答（或自己先看下装到哪个盘） |
| 注册/登录 GitHub | agent 引导你注册或登录，创建私有仓库时你点几下网页 |
| 确认账号操作 | agent 要你输 token/密码时，你亲自操作，别把凭据贴给 agent |

> 说明：环境搭建 agent 会优先用绝对路径自动完成；只有它找不到 Miniforge 时，
> 才需要你到「开始菜单 → Miniforge Prompt」里手动执行它给的命令并粘贴输出回来。

## 验收标准（完成后自己核对）

- [ ] 终端输出「环境 OK」
- [ ] 项目根目录出现 .gitignore
- [ ] git log 能看到 "P0: 环境搭建..." 新提交
- [ ] git remote -v 显示你的 GitHub 私有仓库地址
- [ ] CONTEXT.md 的"当前状态"已更新
